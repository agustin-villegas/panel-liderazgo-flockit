Todos los endpoints cuelgan de `/api` y usan la cookie de sesión, salvo los que se indican.
"Admin" significa rol admin; "Asistente" significa admin o Team Manager; "Sesión" es cualquier usuario
logueado (los datos igual se filtran por permisos).

## Swagger (OpenAPI)

- **Local**: [http://localhost:8000/api/docs](http://localhost:8000/api/docs)
- **Producción**: `<front>/api/docs`, **solo para admins**.

El contrato también se exporta con `uv run python scripts/openapi.py`, y el front genera sus tipos
con `pnpm gen:api`.

## Endpoints

### Salud y auth

| Método | Ruta                 | Acceso  | Descripción                      |
| ------ | -------------------- | ------- | -------------------------------- |
| GET    | `/api/health`        | Público | Estado y versión                 |
| POST   | `/api/auth/login`    | Público | Login; setea la cookie de sesión |
| POST   | `/api/auth/logout`   | Sesión  | Cierra la sesión                 |
| GET    | `/api/auth/me`       | Sesión  | Usuario actual                   |
| POST   | `/api/auth/password` | Sesión  | Cambia la contraseña             |

### Conexiones

| Método | Ruta                                   | Acceso | Descripción                      |
| ------ | -------------------------------------- | ------ | -------------------------------- |
| GET    | `/api/conexiones`                      | Admin  | Lista conexiones (sin token)     |
| POST   | `/api/conexiones`                      | Admin  | Crea (prueba obligatoria)        |
| POST   | `/api/conexiones/probar`               | Admin  | Prueba credenciales sin guardar  |
| PATCH  | `/api/conexiones/{cid}`                | Admin  | Edita                            |

| GET    | `/api/conexiones/{cid}/campos`         | Admin  | Campos candidatos a story points |

### Usuarios

Solo admin. Los usuarios no se borran: se deshabilitan.

| Método | Ruta                               | Acceso | Descripción                                                                             |
| ------ | ---------------------------------- | ------ | --------------------------------------------------------------------------------------- |
| GET    | `/api/usuarios`                    | Admin  | Lista usuarios (nombre, email, rol, activo, último acceso)                              |
| POST   | `/api/usuarios`                    | Admin  | Alta (`first_name`, `last_name`, `email`, `role`, `password` y `password_confirm`, 12+) |
| PATCH  | `/api/usuarios/{uid}`              | Admin  | Edita datos y rol; contraseña opcional (si viene, corta sus sesiones)                   |
| POST   | `/api/usuarios/{uid}/deshabilitar` | Admin  | Deshabilita: corta sesiones y revoca tokens MCP                                         |
| POST   | `/api/usuarios/{uid}/habilitar`    | Admin  | Vuelve a habilitar                                                                      |

Errores de negocio con `409`: email duplicado (`EMAIL_DUPLICATE`) y guardas (`USER_GUARD`): no
deshabilitarse a uno mismo, no quitarse el rol admin y que siempre quede al menos un admin activo.

## Errores

Los errores de negocio salen como JSON tipado (`AppError`) con el código de estado
correspondiente: 401 sin sesión, 403 sin permiso, 404 si no existe, 422 si la entrada es inválida
409 si choca con una regla (email duplicado, último admin) y 502 si Jira falla.
